# Codex Manager v0.6.2

## 概览

`v0.6.2` 是本地代理 OAuth 认证文件导入的聚焦修复版。`v0.6.1` 页面在定版时移除了标签输入，但 Rust/Tauri 命令仍把 `label` 当作必填参数，导致用户点击“导入认证文件”后在 macOS 原生文件选择器打开前即失败。本版恢复参数契约，并保持现有 Keychain、文件权限、凭据格式和信任域边界不变。

本 note 随 tag source 定版，不预先宣称 GitHub Release 已公开。最终 `published` 状态必须以该 exact source SHA 的主线 CI、受保护签名与公证、九项草稿资产回下载复验、人工 Publish 和 published-mode 公开复验为准。

## 主要变化

- CLIProxyAPI OAuth 导入命令的 `label` 改为可选；WebView 不需为已移除的界面字段构造占位值，原生文件选择器可以正常打开。
- 首次导入且未提供标签时由原生层使用安全默认名称；重导入同一 provider 和身份时保留用户既有标签，不静默改写已有档案语义。
- 用户取消文件选择时明确保持无修改；Tauri 返回的固定字符串错误会显示具体原因，不再一律降级为通用失败提示。
- 增加 WebView/原生参数契约、缺省标签、重导入标签保留和空结果分支的回归覆盖，并同步版本号、开发计划与本版发布说明。
- 英文 `README.md`、简体中文 `README.zh-CN.md`、截图/GIF/徽章/下载与 Quick Start 链接、应用功能描述、`PRIVACY.md`、`SECURITY.md`、架构、能力矩阵、供应链、GitHub Description/Topics、平台范围、`LICENSE` 和第三方许可事实均记录为 `no change`：本修复不改变已文档化功能、隐私、兼容性、资产或对外元数据。

## 验证状态

- `implemented`：导入参数契约、空结果处理、固定错误展示和重导入标签保留已进入同一候选源码。
- `tested`：候选源码定版前通过前端 96/96、Rust workspace 128 项通过且 3 项环境依赖测试默认忽略、TypeScript、生产构建、Rustfmt、Clippy、文档同步和 diff 检查；远端主线、签名、公证和资产门禁仍必须在最终 exact source SHA 上独立重跑。
- `observed`：本地调试 `.app` 已构建且调试进程已停止；本机 UI 控制接口无法读取该未安装调试包的无障碍树，因此没有把实际点击、真实 OAuth 导入或上游请求写成已观测。
- 独立审查发现并阻断了“重导入时默认标签覆盖旧标签”数据回归；修复后的针对性原生测试 10/10 通过。

## 兼容性与限制

- 正式资产仍只支持 macOS 13+ arm64；本修复不改变 CLIProxyAPI 内核版本、provider 集合、OAuth JSON 格式、运行时凭据目录或 Codex 配置语义。
- 导入仍要求当前用户拥有、权限不宽于 `0600`、单硬链接、不超过 128 KiB 的普通 JSON 文件，并仅接受已审核 provider 结构。
- 真实 CLIProxyAPI OAuth → loopback → Codex Responses E2E、供应商费用、恢复直连，以及从可信旧签名应用安装更新到 `v0.6.2` 仍需独立验收。

## 隐私与安全

- 本版未放宽原有原生文件选择器、所有者、权限、硬链接、大小、JSON 结构、provider、身份、修订号或 Keychain 边界。
- WebView 仍不获取源路径、原始 JSON、账户身份或 token；错误展示仅使用原生层已限定的固定消息，API Key、OAuth token、bearer、Authorization、Cookie、query 和消息正文仍不进入普通 DTO、SQLite 或日志。
