# Codex Manager v0.6.6

## 概览

本版改进用量与计价可靠性、大目录增量扫描，以及 AGENTS、Codex 配置和代理档案的确认操作。

This version improves usage and pricing reliability, large-history incremental scanning, and confirmations for AGENTS, Codex configuration, and proxy profiles.

同时包含停止代理后的 checkpoint 刷新、完整测试发现、权限契约和文档检查。

It also includes checkpoint refresh after stopping the proxy, complete test discovery, permission contracts, and documentation checks.

已有隔离桌面、人工演示、扫描基准和真实内核空池验证证据；性能结果有明确测试条件。

Evidence covers isolated desktop flows, artificial demos, scanning benchmarks, and a real core with an empty credential pool; performance results have defined test conditions.

真实 OAuth 业务链尚未验收；旧版客户端 updater 安装为 `skipped by user`。 / The real OAuth workflow remains unaccepted; installation through an older client's updater is `skipped by user`.

## 主要变化

- **用量与计价**：异常快照出现后，任务总用量保持 `unavailable`，有效调用仍参与部分估价。活动与计价共用缺失 model/provider/effort 的回退规则，读取批次边界不再改变计价输入。 / **Usage and pricing:** anomalous snapshots leave total task usage `unavailable`, while valid calls remain eligible for partial estimates. Activity and pricing share fallback rules for missing model/provider/effort fields, so read-batch boundaries no longer change pricing inputs.
- **保留期维护**：在启动、设置变更和每小时维护时更新截止时间，在导入事务中清理过期终态任务及关联调用、timeline；保留 checkpoint 并更新删除水位。 / **Retention:** refresh the cutoff at startup, after settings changes, and hourly. Import transactions remove expired terminal tasks and related calls and timeline records while preserving checkpoints and advancing the deletion watermark.
- **AGENTS 编辑与确认**：未保存保护覆盖文件、项目、主导航和窗口关闭；迟到读取不覆盖当前文件，保存期间锁定输入。8 处确认统一使用应用内对话框，覆盖 AGENTS 创建/恢复、配置应用/恢复/删除、外部供应商删除和代理 OAuth 移除。取消、重复请求或页面卸载不会执行待确认写入。 / **AGENTS editing and confirmations:** unsaved-change protection covers files, projects, navigation, and window closing; stale reads cannot replace the current file, and editing is locked during saves. Eight flows use in-app dialogs across AGENTS creation/restoration, configuration application/restoration/deletion, external-provider deletion, and proxy OAuth removal. Cancellation, duplicate requests, and page unmounting cannot execute a pending write.
- **筛选与反馈**：模型、推理级别候选覆盖所选视图全部记录；零结果保留选中值，切换视图清理不兼容条件。保留可操作的原生错误，区分写入失败与写入成功后的刷新失败；确认期间不虚报扫描或保存进度。 / **Filters and feedback:** model and effort choices cover the entire selected view, retain selections with no matches, and clear incompatible conditions when switching views. Actionable native errors are preserved; write failures and refresh failures after successful writes are reported separately. Pending confirmations do not report a scan or save that has not started.
- **代理状态与响应性**：停止成功后重新读取状态与 OAuth 档案，更新上次 checkpoint。首页与代理页复用仅在页面可见时进行的状态校验，不周期读取 OAuth 档案；耗时原生操作进入阻塞工作池。启动健康检查具有 10 秒硬截止期、500ms 请求超时并禁止重定向；状态查询不清理 runtime 或恢复安装事务。 / **Proxy state and responsiveness:** successful stops refresh status and OAuth profiles, including the last checkpoint. The overview and proxy page share status checks while visible, without periodic OAuth-profile reads; slow native operations use the blocking pool. Startup health checks have a 10-second hard deadline and 500ms request timeout with redirects disabled. Status reads do not clean up the runtime or recover installation transactions.
- **增量扫描**：优先处理 watcher 报告的变更文件，使用有界历史发现游标与公平续读队列，保留读取预算和每 60 秒 reconciliation；每次增量不再要求先遍历、排序全部历史文件。 / **Incremental scanning:** prioritize watcher-reported changes, use bounded resumable history discovery and fair continuation queues, and retain read budgets and 60-second reconciliation. Each incremental update no longer requires a full history walk and sort first.
- **测试与文档检查**：Node.js 24 原生自动发现测试；WebView commands 与 Tauri allow 权限按完整集合校验。文档检查覆盖双语版本、平台和下载事实、本地链接、锚点、非空资产及可选外部 URL。默认关闭的隔离桌面 QA feature 仅支持 debug 构建。 / **Tests and documentation checks:** Node.js 24 discovers tests automatically; WebView commands and Tauri allow permissions are checked as complete sets. Documentation checks cover bilingual version/platform/download facts, local links, anchors, nonempty assets, and optional external URLs. Isolated desktop QA is disabled by default and restricted to debug builds.

## 兼容性与限制

- 支持平台仍为 macOS 13+ Apple silicon；新增 SQLite 迁移 14 和受限活动候选读取命令，不改变 Codex 配置格式。 / Platform support remains macOS 13+ on Apple silicon. This version adds SQLite migration 14 and a restricted activity-options command without changing the Codex configuration format.
- 已有非空调用模型保持原值；未观测终态或缺少有效时间的任务暂不自动清理，OAuth 与 AGENTS revision 的独立保留规则不变。 / Existing nonempty call-model fields retain their values. Tasks without an observed terminal state or valid timestamp are not automatically removed; separate OAuth and AGENTS revision retention rules remain unchanged.
- 50,000 个人工历史文件下，变更文件到 checkpoint 的 p50 从 215.017ms 降至 1.037ms（约 215 → 1.04ms）。这是 macOS aarch64 debug 暖缓存、每规模 5 次、49,999 个空文件和 1 个增量文件的结果，不含 watcher debounce、UI 刷新或真实历史正文解析；不代表真实目录的固定性能提升。 / With 50,000 artificial history files, changed-file-to-checkpoint p50 fell from 215.017ms to 1.037ms (about 215 → 1.04ms). This macOS aarch64 debug warm-cache benchmark ran five times per scale with 49,999 empty files and one incremental file. It excludes watcher debounce, UI refresh, and parsing real historical bodies, and does not establish a fixed speedup for real directories. [原始样本 / Raw samples](https://github.com/ewsun22/codex-manager/blob/45ba52328082b2360879cb9d46cdefc3a7f48362/docs/validation/scanner-benchmark-2026-09-06.json)
- 真实 OAuth 成功请求、上游 5xx、checkpoint 刷新与 Codex Responses 完整业务链及费用验收尚未完成。旧版客户端 updater 安装按用户要求为 `skipped by user`，不属于本轮完成条件，也不标记为通过。 / Real OAuth success, upstream 5xx, the complete checkpoint-refresh and Codex Responses workflow, and billing acceptance remain unverified. Installing through an older client's updater is `skipped by user`, is outside this round's completion criteria, and is not reported as passed.

## 隐私与安全

- 官方 OAuth、CLIProxyAPI OAuth 与 Codex 配置三个信任域及内核审核基线不变；AGENTS 草稿只在内存保存。API Key、token、bearer 和消息正文仍不得进入普通 DTO、SQLite 或日志。 / The three trust domains for official OAuth, CLIProxyAPI OAuth, and Codex configuration, and the reviewed core baseline remain unchanged. AGENTS drafts stay in memory; API keys, tokens, bearers, and message bodies remain excluded from ordinary DTOs, SQLite, and logs.
- 主窗口新增受限活动候选读取权限及用于关闭保护的 `core:window:allow-destroy`。HTML dialog 不增加原生权限；未添加通用文件、HTTP、shell、process 或 dialog 插件权限。 / The main window adds restricted activity-option access and `core:window:allow-destroy` for close protection. HTML dialogs require no added native permission; no general file, HTTP, shell, process, or dialog-plugin permissions are added.
- 隔离 QA 使用人工数据，禁用认证 backend 和敏感命令；release 构建拒绝 QA feature。测试观测不代表所有上游错误路径或真实凭据均已验收。 / Isolated QA uses artificial data with authentication backends and sensitive commands disabled; release builds reject the QA feature. These observations do not establish acceptance of all upstream error paths or real credentials.
