## CLIProxyAPI OAuth → Codex Responses

执行前需要指定测试档案、允许的模型和调用费用上限。凭据通过现有受控导入/启用流程进入独立 CLIProxyAPI Keychain，不在本文或终端输出原始认证文件。不能使用官方 Codex OAuth 档案替代 CLIProxyAPI OAuth，也不能为了关闭验收项创建临时供应商密钥。

准备和执行顺序：

1. 核实测试档案及启用状态、现有代理进程/端口与待恢复的 Codex 配置状态；只记录脱敏标识和哈希。
2. 在明确的测试环境中启动已审核 CLIProxyAPI 内核，验证绑定 IPv4 loopback、无认证访问为 401、禁用管理端点和正文日志。
3. 使用用户选择的测试模型提交一个最小人工 Responses 请求，记录成功终态、实际模型、用量和费用来源；未取得实际响应不能用健康检查替代。
4. 停止代理并验证 OAuth checkpoint 更新、私有运行目录清理、进程/端口释放；确认前端停止状态及 checkpoint 时间一致。
5. 若本次明确包含 Codex 配置切换，验证配置恢复、哈希/CAS 与直连行为；否则保持这一子项未执行，不能声称配置往返已验收。

失败时先读取操作结果与进程归属，避免重复请求或重复计费。checkpoint 失败时保留恢复证据，不能强删未知进程或遗留认证目录。
